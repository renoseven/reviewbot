# 对话记录规则

## 需要一条可复用的对话记录规则

### 意图

- 增加一条 Cursor rule：整理、保留并优化对话记录，记下关键步骤，按对话落到独立文件。原始对话精简保留，用来确认用户意图。栏目尽量精简，但保留有效信息。问题之间要能一眼分开
- 同一类问题要合并
- 意图要只看这一段就能核对当时要什么；不要只留下「上面那条」这种指代
- 描述要么不要 1、2、3 这种，要么逐项列举

### 步骤

- 新增 always-apply 规则 `.cursor/rules/conversation-notes.mdc`
- 记录放 `docs/conversations/`，扁平文件，命名 `NNN-slug.md`，不含日期
- 每个问题一套：标题即问题（`## 短句`）；段为意图、步骤、决策；套与套之间用 `---` 隔开；未决放文件末尾
- 同类合成一套并回写已有套；不同类才分开写、按栏目不合并
- 意图改为自洽：指代展开；多项要么连贯短句不夹编号，要么逐项列举

### 决策

- 记录放 `docs/conversations/`：需要进仓库、给人读
- 每条对话一个 `.md`，不套子目录
- `alwaysApply: true`：对话流程，不绑特定文件类型
- 文件名用序号、不用日期
- 禁止整段 transcript，精简保留原话
- 每个问题一套：标题即问题（`## 短句`）；段为意图、步骤、决策；套与套之间用 `---` 隔开；未决放文件末尾
- 同一类问题合成一套，不要平行再开一套：同类追问并进已有套
- 为什么不是按栏目把整份对话收成三个大段：不同类问题混在一起就对不上「当时要的是什么」
- 意图只看这一段就能核对当时要什么；指代必须展开；展开后要么连贯短句、要么逐项列举
- 为什么不是整段粘贴用户消息：寒暄和编号外壳可以扔，所指内容必须留下
