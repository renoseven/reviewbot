# Rust 编码与测试规范

## 按设计补 Cursor rules

### 意图

- 根据 `docs/design.md` 补充 Rust 编码规范 + 测试规范，放到 rules 里面
- 不要写依照 docs.design.md，这样占用太多上下文了
- 编码还有一条，实体尽量对象化，做到高内聚低耦合
- 最外层错误可以使用 anyhow
- 单元档不要写成测 domain（对齐、引文、去重是 merge 的算法）
- 对象化例子要写清主人，对齐不要写在 ChangeSet 上
- 规定最长 5 个参数，超出可以用 context
- 命名禁止生僻词汇
- 改一下 alwaysApply
- 禁止口语化命名
- 给了一份编码规则新稿（文件切分、封装、必须实例化、配置量纲、禁止 unwrap），测试规则没给新稿；要先改就直接改，记进这份对话，不另开文件

### 步骤

- 从设计抽出写代码会踩的边界：分层与入口、类型归属、硬约束的代码形状、测试分档与模块边界
- 写成 `.cursor/rules/rust-coding.mdc` 与 `.cursor/rules/rust-testing.mdc`；编码钉分层、类型主人、硬约束；测试钉五档、离线、只在最低档测；用例清单不搬进 rule
- 删掉指向设计文档的引言，把「不要测」写成自洽的理由
- 加「实体对象化」：行为写在主人 `impl` 上、变化点用 trait、一类型一事；`domain` 是共享词汇例外
- 加「错误」：库内 `thiserror`，`main.rs` 可用 `anyhow` 收口
- 单元档改为测设施与阶段内纯算法；对齐例子改成数据在 `ChangeSet`、算法在 `Merge`
- 参数超过 5 个（不含 `self`）才收成只读 context；命名用常见英文词，禁止生僻词和口语化
- 两条 rule 都改成 `globs: **/*.rs`、`alwaysApply: false`
- 只改 `rust-coding.mdc`：补「不是一个类型一个文件」、配置命名量纲、一次 run 一个 worktree、去掉 `scratch/`；分层、`include_str!`、不改模型给的数、安全靠实现留下
- `rust-testing.mdc` 未动

### 决策

- 拆成两条而不是一条：编码管「代码长什么样」，测试管「行为落在哪一档」
- 不另写通用 Rust 风格（unwrap、rustfmt）：设计没定的不发明。配置字段名要说清量纲与主语，带单位的写进名字
- 为什么不把四十多条用例抄进 rule：清单会漂，rule 只留分档原则
- rule 必须自洽，不靠「去设计里找」；需要改设计时再显式打开，不由编码规范间接拉取
- 对象化指「数据 + 属于它的行为」用 struct/impl/trait 收拢，不是继承、也不是给 `ChangeSet` 塞业务方法。为什么不是并进「类型跟主人走」：主人解决放哪一层，对象化解决类型内部怎么长
- `anyhow` 只停在二进制最外层；库的公开错误仍是可匹配类型，否则退出码和重试策略对不上
- context 不是开了就能当上帝对象：只装这一次调用用到的依赖，字段私有、默认只读
- 为什么不是 alwaysApply：改文档不必吃进 Rust 规范；有 `.rs` 在上下文里才加载
- 禁止口语化和禁止生僻词并列：一边不要偏词，一边不要随口起名
- 测试规则不动：与现有五档对齐，也没有新稿
- 编码规则不整份换成新稿：分层和产品硬约束留下。`scratch/` 与双 Source trait 会把实现往回拉，改成一次 run 一个 worktree，平台 API 是它的可选属性
- 「禁止自由函数 / 必须实例化」这次不写，和「不把自由函数改写成方法」冲突；封装分块、`unwrap`、成熟库后加
- `domain` 不再钉死「只有三个类型」，仍要求新类型先证明没有主人
- 规则由人改；按规则落地时仍不许改 `.cursor/rules/`
