# 决策记录

从历次对话收出的现行取舍。只写还成立的点和一句理由；被后话推翻的以最终结论为准。现行设计见 [design.md](design.md)。

对话原文仍在 [conversations/](conversations/)，不再追加。

---

## 产品形态

- **核心是切分 → 带工具打分 → 按分定级。** 体量在配置、硬约束、CLI、平台接入，不在主流程；文档先把回路说清，避免读起来像流程很重。
- **先走通含发帖的窄链路，预扫和深度后加。** 发布晚来会改 `input` / `merge` 的数据形状；工具加的是同一条回路上的深度。
- **做 CLI，不做常驻服务。** CI 已经提供调度、密钥注入和日志；预算按 run 冻结，状态模型贴合一次性进程。
- **只支持 Linux（含 WSL）。** 目录锁是 `flock`，默认路径按 Unix home 写；不承诺 macOS / Windows 的工具链、链接器和 `PATH`。
- **评审结论不进退出码。** 「工具自己出了问题」和「代码里有问题」不能塞进同一个通道；要卡流水线从 `summary.json` 自己判。
- **reviewbot 自己不克隆仓库。** 内置 clone 是全文唯一会往磁盘写工作树、还要起 git 子进程、并拿评审对象控制的地址发请求的路径。
- **许可证 MIT OR Apache-2.0。** Rust 生态默认组合，Apache-2.0 带专利授权；依赖不挡。

## 模块与命名

- **没有编排模块。** 拆开看几乎全是 `config` / `record` 的活，剩下二三十行顺序；`pipeline` / `runner` 被 CI 占了，`orchestrator` 是施事者名词，现有模块全是主题名词。阶段顺序只写在 `lib.rs`。
- **`input` 与 `platform` 分开。** 「变更长什么样」和「怎么从平台拿到它」是两件事；原始 diff 根本不碰 `platform`。
- **行号对齐与引文核对合进 `merge`。** 两者都要拿分片上下文回查，拆开要来回传参数。
- **`domain` 只装找不到主人的共享词汇。** 它存在的理由是打断依赖环；能找到主人的类型跟着主人走。
- **`common` 只收没有主人的横切能力**（退避、HTTP 传输、密钥读写、截断）。脱敏、路径策略、子进程清洗仍是 `security`；密钥进 `common` 是为避免 `config` ↔ `security` 成环。
- **安全靠实现保证，不靠类型闸门。** 校验点只设在 `tool`：模型能看见的读取全从内建 tool 进来。`RepoSource` 跟 `platform`，`Worktree` 跟 `worktree`。
- **阶段名是动作。** `merge` 不叫 `finalize`（后者说何时不是做什么）；`plan` 不叫 `triage`（一个拼写同时是屏幕、配置、落盘）；`protocol` 不叫 `llm`（与配置字段对上）。
- **`api_token` / `api_key` 的 `api_` 不许省。** `token` 已被 LLM 计量单位占用；两个值都去第三方界面现取，名字对上人家的说法比配置内部对称更值钱。
- **查看类命令名单数，JSON 顶层键复数。** 「一个块声明一条」与「一个键装很多条」是两个问题；旧复数不留别名。

## 配置

- **一个设定只有一个来源。** 团队约定进配置，机器事实与本次调用进命令行；为一个设定另开可覆盖字段会悬空、要解释优先级。`[security]` 禁止命令行覆盖。
- **配置只从 `--config` 读，默认 `~/.reviewbot/config.toml`。** 配置装着令牌与预算，属于这台机器怎么配的，不属于当前站在哪个目录；不从 cwd 查找，不再认 XDG。runs 默认 `~/.reviewbot/runs`。
- **`--config` 指进工作树只 warn、不硬失败。** 本地在自己仓库里跑是正常用法。
- **没有 `review.guidelines`，配置不能从仓库读。** 要当项目策略就得进仓库，一个 MR 改掉它就能对自己网开一面。
- **段名 `[review]` 不是 `[llm]`。** 按阶段并列；`[llm]` 会与 `[[model]]` / `[[provider]]` 抢位置。
- **`default = true` 标在模型条目上。** 不另开 `[review].model`（能悬空），不用 `alias = "default"`（简称空间无提示碰撞），不取数组第一条（书写顺序变成语义）。
- **不允许运行时静默降级到便宜模型。** 账单和结论都会失去可解释性。
- **单价、`context_window_tokens`、`max_output_tokens` 全部必填。** 没有单价算不出预算；猜上下文默认值的代价是跑到一半被厂商 400 打回。
- **带单位的字段把单位写进名字，主语写清是谁的上限。** `budget_per_run`、`context_window_tokens`、`max_file_bytes`、`max_files_per_listing` 这类；省掉量纲之后，月度额度、窗口字符、一次调用与整次 run 会对不上。
- **`[review]` / `[plan]` / `[security]` 里代码选不了的数值一律必填。** 正确值被模型窗口和仓库规模夹着，代码替你选一个、选错时症状安静（掐断、窗口没地方放 diff），报告上跟干净通过长得一样。用 `0` 当未配置，校验走 `validate` 而不是 serde 必填（整段都可以不写）。
- **布尔项保留默认值。** `true` 和 `false` 都是正当取值，没有「未配置」可言。
- **`[log]` 不进指纹。** 它属于「这台机器怎么配」；想看细一点日志不该作废全部 checkpoint。`RUST_LOG` 仍可临时覆盖。
- **`deny_paths` 黑名单，不要目录白名单。** 白名单把「能不能读」和「仓库长什么样」绑死，一份配置评任意仓库会退化成 `["."]`。拦住读到仓库外的是工作树根与平台 API。
- **`allow_extensions` 必填白名单，没有内置默认。** 空列表的语义只能是「什么都不许读」；主闸在 `plan`，和 `deny_paths` 同一层——只挡工具读、不挡把 diff 送给模型，名单去掉 `md` 仍会给 markdown 花钱。列表与搜索不按扩展名滤：存在与否本身是答案。
- **尺寸旋钮在 `[review]`，不在 `[security]`。** 调大 `max_file_bytes` 只是往内存多拉一点（额度）；调大 `allow_extensions` 才是碰本来碰不到的文件（边界）。
- **配置里没有取值范围也没有格式的字符串，启动就拒绝。** 这种参数等于没声明，模型在猜，猜错的成本落在外部命令上。
- **没有 `enabled`。** 不写 = 不启用；`enabled = false` 制造「写着却不生效」。
- **密钥只写来源，不支持 `cmd:`，值长得像密钥就拒绝启动。** 违反不执行任意代码。
- **`[[model]].name` 是厂商真名，`alias` 是可选简称。** 真名是外部事实；把简称当主键会在请求日志里对不上。
- **`reasoning_effort` 挂在模型条目上。** 同一模型要两档就复制一条换 alias；不用 `none` 当截断补丁。
- **平台表用已知 host 定实现，配置不设 `kind` / `host`。** 网页 host 从已知 API 推出；未知 host 不该靠多写一行去猜。`base_url` 是拼接前缀，不是可直接请求的地址。
- **TOML 数组段名单数（`[[model]]`）。** 一个块声明一条，Cargo 的 `[[bin]]` 同理；Rust 字段保持复数，靠 `serde(rename)` 接。旧复数不留别名。
- **协议名缩成 `openai`。** `name = "deepseek"` 配 `protocol = "openai"` 不矛盾：一个是厂商，一个是请求线。

## 切片与评审范围

- **一文件一分片，只评改动；关联文件由模型按需去取。** 不按 token 余量拼文件：模型会拿相邻文件互相脑补，而凑巧挨着不等于互为上下文。
- **不按路径加权。** 「`src/` 比 `tests/` 值钱」是项目策略；不想看的目录写进 `skip_paths`。
- **范围校验用变更行，对齐用可评论行。** 上下文行是没动过的代码，混在一起会把「能挂在哪儿」和「能评什么」当成一件事。
- **越界整条丢弃，不降级。** 这是该不该出现在这次评审里，不是说得准不准。
- **去重必须可判定。** 同一 path、区间相交、正文规范化后逐字相同才合并；「语义相同」reviewbot 判不了，宁可漏合也不错合。
- **单文件被切开时带摘要交接，不共享对话。** 整份放不进窗口才切，把前几片的 diff 再带上就是把放不下的东西再放一次。交接那句话由模型自己写；交接段只在真切开时出现。
- **`trace_id` 只在切开时加后缀。** 未切开是绝大多数情况；统一加会让「一个文件一个 trace」看不出来。后来改成与 `run_id` 同形的十六位十六进制，路径记在 JSON 里。

## 分数、意见与结束信号

- **严重程度与置信度都由模型给 0–100，reviewbot 一个都不改。** 「工具扫出」是核对出来的事实标签，不参与定分；核对只能证明这句话是工具说的，证明不了工具说得对。
- **两个数不合成一个。** 公式看不出「三条中危其实是同一个设计问题的三个面」；合成本身就是替读的人做权衡。reviewbot 只做排序（先严重、再确定），不做加权。
- **两轴同一套区间端点，档位名各用一套。** 端点一致是为了只学一张表；名字分开是因为一条意见上出现两个 `high` 分不清。
- **问题和改法拆成 `body` / `suggestion`。** 不混在一段里；缺一则整条丢弃。
- **意见用 `submit_comment` 交，不用聊天正文里的 JSON。** 散文里抽 `path` / 行号 / 分数 / 依据比解析 JSON 更脆，还会按条数放大费用。围栏是「模型把 JSON 写进正文」才有的问题，换成 function call 之后一处不剩。
- **结束信号只有 `finish_review`。** 「这里没问题」没有形状可认，任何正文闸都是靠猜；会 function call 的模型不把纯文本当成终止动作。空 `submit_comment` 拒绝并回传 finish；submit / finish 不记入调查轮数。
- **没有可定位的缺陷就不要调 `submit_comment`。** `path` 省略填本分片；空调用（没 body 也没 suggestion）当没有意见；有 body 却空 suggestion 仍拒绝。
- **不加内容过滤。** 校验管形状、不管内容；1% 已经是模型在说「我没东西」。再猜哪条「没内容」，是拿误伤真实的简短意见去换拦住模型自己犯的错。
- **汇总打分也是工具调用（`submit_summary`），分由模型给。** 不按发现条数套公式；必须在剔除与去重之后，发出去的数字和发出去的评论才对得上。只喂最终清单，不重发 diff。预算不够就跳过打分，不填 0。
- **没发现问题也要 overall。** 空清单是合法结论，不能显示成 `not scored`。
- **全空白的总结拒绝。** 去掉空白后仍然算通过，等于接受一句空话；被拒后重问，两次都空记为未打分。
- **收尾由 reviewbot 主动发起。** 工具轮撑长、预算不够、窗口顶到、输出被截断时自己转入收尾，不靠厂商返回错误来兜底。
- **发布按「文件有没有有效评论」过滤。** 标志由 merge 从幸存评论推导，不进模型输出；出错、没评论、条目全被丢掉都不算有效。切成多块的同一文件只占一行。

## 工具与 worktree

- **一个工具只有一份说法。** 名字、描述、参数、用途、轮次、前置条件是同一份事实；分开写就会分开漂，而模型只信它读到的那一份。
- **参数声明是源头，给模型的 schema 是派生物。** 手写厂商格式的字面量意味着「怎么写」和「怎么读」各有一份事实，校验与描述会对不上。
- **调用前的校验、路径检查、上限在同一层做，拒绝理由回传给模型。** 模型据此改参数再来一次；拒绝是对话的一部分。
- **被字符串化的整数按整数读。** 模型这么写的频率高到拒绝只是白花一个来回，且重来的值一模一样。
- **工具按用途分，不按「内建 / 配置来的」分。** 内容、检查、交付决定答案意味着什么、哪一轮给；写在哪只是实现。
- **一轮里模型看得见的工具，必须等于它这一轮能调的。** 调查、收尾、打分各自只给对应的那些；给一个这轮调不动的，等于给一个必然失败的动作。这管的是轮次，不管 worktree 答不答得上来。
- **prompt 点名的工具必须是 registry 里有的名字。** 讲一个不存在的名字，模型会把「调不到」读成「仓库里没有这个东西」。
- **次数和尺寸上限写进该工具自己的描述，作为作用的一部分。** 模型不知道一次最多能读多少就只能靠撞；描述和配置是同一份事实。cache / checkout 仍不写进每条描述。
- **保留名单必须与实际内建名对等。** 对不上时，配置里的工具能用内建名盖掉内建工具；用例钉住，以后还会漂。
- **工具一律由模型按需调，没有预扫、没有 `skippable`。** 程序不知道哪个检查器配哪个文件，那个知识只在 `description` 里；预扫会让每片都背着其余文件的告警。
- **外部命令就是一个工具，和读文件走同一条调用路径。** 差别只在用途；架构上分成两类会让每加一个能力都要问「它算哪边的」。不走 MCP：形状相似是趋同，信任边界是反的。
- **外部命令的参数是数组，直接交给操作系统，不经 shell；子进程拿不到凭据。** 这是安全边界。
- **内建不进配置。** 可配字段改不动实际行为，漏写会静默关掉读上下文的能力。
- **不做 `diagnostics` 解析。** 编译器输出本来写给人读；要求先声明格式等于给「加一段 `[[tool]]`」加过路费。
- **工具全量注册，能力是 worktree 的属性。** 「看得见的永远等于真能调的」代价是 prompt 只能泛泛讲工具，模型从一张无从核对的清单反推能力；「这次不值得去看工程」该由模型看着 diff 做。调用被拒时说明这是本次 run 的限制，不是关于代码的答案。
- **许可不是能力。** `requires_build` 要的是运维授予的 `[security].allow_build_tools`，混进能力集合会让「这次做不到」和「你没批准」共用一套话。
- **`Worktree` 是 enum 三个变体，不是扩展点。** `Empty`（纯 diff 且无平台）、`Local`（命令行给的检出，只读）、`Cache`（`<run_dir>/cache`，按需从平台取回）。变体只在带不同数据或允许不同操作时才值得；写盘只有 `Cache` 握着 root 与 repo 这一对。scratch / 在线模式这些说法取消：平台 API 是目录缺文件时的补给，取回落盘之后跟检出里的文件没有区别。
- **`Cache` 的生命周期不超过这次 run，清 run 就带走，不跨 run 复用。** 复用需要按提交归档与失效；没有那套规则的复用是脏数据。
- **取回落盘只管安全：路径不越界、不留执行位、二进制不落盘。** 能取多大是 `max_file_bytes`；读多少是读的人的事。
- **`Cache` 上列仓库与搜仓库转发平台，绝不用盘上已有文件回答。** 本地回答会把「取过什么」说成「仓库里有什么」，一次未命中就被读成「不存在」。
- **本地与仓库拆成不同的工具。** 列仓库和列本地是两个动作；要正文就先 `fetch_repo_file` 再 `read_local_file`。当年反对的是两个名字答同一个问题，不是故意揉在一起。
- **两种搜索引擎不再坍缩成一个。** GitLab 上 regex 与 keyword 是两个索引、覆盖面不一样；一次调用恰好一个引擎，所以 `SearchKind` 是枚举不是位。
- **删除 `Reach` / `Abilities`。** 变体定下来之后条件直接对着它们说，中间那层影子词汇没有用处，且位集表达不了「或」。
- **`Repo` 跟主人走，落到 `Platform::repo()`。** 两个访问器永远一起用，分开就能把某个平台的 source 配上不属于它的能力。
- **不给内建 tool 加各自的调用次数上限。** 该读几个文件是模型看着 diff 才判断得出来的；成本已经有轮级输出额度、预算和上下文检查在管。
- **检查器适用语言写进描述，不在代码里按扩展名拒。** 闸若挂在路径上，`.rs` 会读不到、`submit_comment.path` 也会被拒。不点名 Rust：点名会把闸读成「这份仓库的例外」。
- **独立单文件检查用 `cppcheck`，编译器保持 `requires_checkout`。** 缺工程头文件会刷一屏 missing include，比不跑更糟。`typecheck` 是题目点的名字，实现仍是 `gcc -fsyntax-only`。
- **未调用的检查器不进报告、不 warn、checkpoint 里那份名单也删了。** 没调是模型按描述做的判断（C 检查器没打到 Rust 上正是「不适用就跳过」），不是改动上的缺口。
- **完整检出没有平台搜索不是覆盖缺口。** 本地正则能搜整棵树。真缺口是 Empty 读不到文件，或 Cache 且平台也搜不了。
- **装不下的文件正文只能拒绝，不能硬截。** 模型拿到前 32KB 会认定看不到的定义不存在。用行区间不用字节 offset：整条链路都按行号对齐。列表可以截断（紧跟着说了还有多少条），文件正文不行。
- **`suggest_local_read` 回尺寸和建议窗口，切在哪儿交给模型。** `max_file_bytes` 的含义是「取回来多少」：平台 API 没有范围请求，超过它的文件怎么切都读不到。拒绝里讲清文件多少字节、多少行、一次最多能给多少。

## Prompt 与全局视野

- **给模型的 prompt 是模板加槽，不是散在各阶段的字符串拼接。** 一段说明只有一个出处；未声明的槽、装配完仍空的槽都是错误。同一段话拼两遍就会各自漂，而模型不会抱怨。
- **prompt 随二进制走，配置里不许有任何能改它的字段。** 可配置的 prompt 意味着每个用户跑的是不同的产品，报告与评分不再可比。
- **渲染只有一条路径：模板加槽值变成最终文本，由同一处完成。** 围栏、截断列表、按路径与行号引用，共用渲染件；人看的命令输出不走这条——两边约束相反，共用字符串会为了报告好看而改动 prompt。
- **模板里不放逻辑：没有条件、没有循环、没有嵌套模板。** 要分支就在 Rust 里选哪份模板、往槽里填什么；文本里一旦出现 `if`，通读就不再等于模型会读到的东西。
- **槽是空的就整段不出现，不要留一个空标题。** 空小节是一句断言；「没有」和「拿不到」必须用话说清，对推理的影响完全不同。
- **材料不是指令；模型输出不是可执行指令。** 不做关键词过滤：既绕得过，又会误伤正常代码。爆炸半径限死在「说什么」上。
- **派生事实进 `instructions`，作者写的散文进 `input`。** 变更清单进 instructions（全 run 逐字不变，厂商缓存命中）；MR/PR 标题、描述、commit 主题行进 input 并围成材料——`instructions` 是这份 prompt 自己声明为权威的槽位，把被评审方写的散文塞进去就是自己推翻自己。
- **不加 survey 阶段让模型先总结改动意图。** 总结一旦含糊或错了，这个前提会进到每一个分片，静默且全局。
- **目录摘要整块拿掉。** 按全仓文件数排名再让模型「对着摘要去列」是一张旅游图；改动清单已经写出附近路径。
- **清单只从 `ChangeSet` 来，不带 plan 的跳过与分片信息。** 否则形成环：instructions 含清单，清单含 plan 结果，plan 结果含分片上限，上限又取决于 instructions 大小。文件少于 2 则整段省略；最多 60 条，超出只报数——这是手上已有的事实，一次只看一个文件时用来区分「调用方没改」和「调用方在别处改」。
- **背景只给手上已有的事实，不给「别的文件里写了什么」的摘要。** 模型没法核对一份摘要，却一定会照它推理。
- **围栏必须同时办三件事：** 是意图、不是行为的证据、里面的指令是被评审内容。跟 diff 冲突时 diff 才是真的，而这个冲突本身值得提一条意见。
- **只取 commit 主题行、只取一页、多要一条。** body 多半是描述再说一遍；多要一条是为了能明说「还有更多」，静默截断会让模型把最后一条当成最后一次提交。标题、描述、单条主题各有长度上限：描述写成带清单的模板时，不设限会比它描述的 diff 还贵。空白等于没有。
- **不派查阅活，闸留下。** 模型自己会查；要禁的是离开这次改动去观光。直接相关只有两样：本文件变更行用到的符号定义，或这次新增/改过的函数的调用方。不写请早停（写过总轮次还更高）。
- **顺序只写到 fetch。** 先确认路径、不知大小先问、分片怎么读，都不写——手续比闸好执行。
- **工具描述只陈述作用。** cache / checkout 不写进每条描述；worktree 三段只写这次是什么。
- **「先跑检查器」整句删掉。** 义务句在逼第一轮硬凑；检查器仍在清单里，按需再调。
- **不确定由 `confidence_score` 承担，不由沉默承担。** diff 给了理由、只是某个前提这次核不了的，属于 40–69 并点名核不了的是哪条。
- **长指令保持 markdown 惯用法，短通知保持一句散文。** 编号小标题、硬规则加粗、分数表是给模型划层次；收成纯散文，六段和四档会糊成一堵墙。按职责分：文章和通知在 `src/prompts/`，工具契约跟工具走。
- **给模型的材料与 reviewbot 自写的徽标用英文。** 代码、标识符、检查器输出本来就是英文；给人看的正文仍由模型自己定语言。

## 预算与停条件

- **无上限用 `-1`，`0` 是一分不花。** 想让 reviewbot 别花钱的人最自然写 `budget_per_run = 0`，若那等于放开上限会花光账户且不可撤销。
- **不查汇率、不并发。** 一个「10 元预算」的工具引入外部行情源，代价不成比例；并发会让调用前检查失效。
- **不预测单次调用花费，只累计真实账单。** 缓存命中率不稳定，当不了闸门。只留精确的那一半：输出单价已知且从不走缓存，`剩余 ÷ 输出单价` 写进请求的 `max_output_tokens`。
- **接受一次调用的输入作为超支上界。** 换来的是没有任何一次调用因为猜错被误拒。
- **留一笔给收尾，开局不留。** 花了钱却什么都没换回来是最坏的结果；开局那轮还没查到东西，留了反而让小预算起不了步。
- **低于 1024 token 的输出额度直接拒绝。** 否则最后一点钱买回来的只是一句被截断的话。
- **停有两道，都不按整次 run：** 下一轮装不进窗口，或调查轮次碰到 `[review].max_rounds`。`of` 只报配置，不拿当时窗口还能再装几份去改分母。
- **轮数上限是防死循环的护栏，不是成本闸门。** 钱由 `budget_per_run` 在每次调用前拦住；把轮数定紧一分钱也省不下，只会让评审看得更少。不交给模型规划轮数。
- **`max_tool_output_bytes` 留下。** 它是关于工具的事实（一份诊断读多少才有用），换个模型也是同一个答案，而且 registry 构造时窗口还没划分。

## 恢复、身份与落盘

- **`review` 是进入一个 run 的唯一命令。** `run_id` 是输入与配置算出来的，而这两样正写在那条命令上；`resume` / `publish` / `report` 没携带任何新信息，删掉它们同时删掉三份要维护的分歧。
- **`run_id = hash(输入标识 + head_sha)`，配置不在里面。** 同一输入同一 commit 命中同一个目录；配置改了仍进同一个目录，从最早受影响的阶段起重跑。指纹进 `run_id` 会为每次改配置留下孤儿 run。
- **输入身份或 `head_sha` 对不上直接失败。** `--run-id` 是唯一能让命令行与目录对不上的入口，同受这道检查。
- **`--publish` 不进指纹，但每次按命令行重写意图。** 先看报告再加 `--publish` 命中同一 run；带过 `--publish` 的 run，下次不带着它再跑就清成「不发」。
- **report 与 publish 拆开，每次进入都跑。** 渲染只读盘、必须免费；发帖必须联网、必须幂等。合在一起时这一半的代价就是另一半的代价。`publish` 不看自己的 checkpoint，该不该发由 MR 上的标记加 `published.json` 决定。
- **失败点是分片，不是整个 review 阶段。** 每个 chunk 成功后立刻落盘；同一份 checkpoint 文件，完成标记另走。handoff 必须进这份快照。花费跟每次模型调用走，不跟 chunk 绑定。
- **锁归内核（`flock`），文件只是线索。** 进程怎么死都释放，「过期的锁」不存在；干净退出也不删 `lock` 文件，以免 unlink 与 close 之间开竞态。锁在开 worktree 之前拿。
- **正常流程一个 run 都不删。** 一个要花钱、还可能往别人 MR 上写字的命令，不该顺手删数据。只有 `run prune` 删；默认 `--keep-latest 0` 即清空，产物靠 `--output-dir`。
- **checkpoint 与 trace 一律 JSON 明文。** 九成是长文本，换编码只省键名；run 目录要在 reviewbot 自己出问题时给人看。
- **`--output-dir` 留着，run 目录不能当 CI artifact。** internal 视图里有 published 刻意剔掉的文件正文；默认做法应该就是安全的做法。
- **stages 文件名只留阶段名，不带编号。** 顺序已经在 `Stage` 上，再写一遍编号只会在改顺序时留下对不上的旧文件。
- **完成状态只能是前缀（`completed_through`）。** 排除不可能的离散集合，损坏阶段及其全部下游一起作废。
- **痕迹知道自己属于哪个阶段，重跑只清本阶段。** 阶段名是字段，不是正文前缀——靠字符串匹配来认，下次改一个字就清不掉；读的人必须能分清「模型只查了半程」和「行号被移了一位」。

## 报告、日志与终端

- **给人看的是结论和查找键。** 报告和 MR 评论只留结论与 `run` / `trace`；调用过程在 `traces/`；花费给操作者看，走 CLI 和 `summary.json`。budget 不出现在报告和评论中。
- **挂点（`start_line` / `end_line`）进报告标题，依据（`evidence.lines`）不印。** 挂点可以是上下文行；依据至少一行必须落在变更行上。不能拿依据的最小最大当区间——四处同一问题不是一段连续代码。
- **`cut_short` 不进报告。** 调查用尽仍要模型按已有的交，那不是覆盖缺口；未评审只列一次都没打开过的文件。缺内容能力时，`unavailable` 印在模型那段话之前，框住那段话的全部。
- **日志一个字节都不上 stdout / stderr，写进 `<run_dir>/log`，追加写。** 最需要日志的正是非交互、事后才看的场合；`-v` 删掉。`-q` 只压终端。
- **状态屏的字段就是最终摘要的字段。** 另起一套进度词汇，跑完那一刻屏幕上会换一套词。只为已知的字段留行；`, from checkpoint` 必须有，否则观察者会把没人干过的活报成干过了。
- **`progress` 不是扩展点。** 没有哪件事可以取决于谁在看；`Silent` 必须是一个完整答案。不搭在 `tracing` 上：日志是事后散文，事件是关于还在跑的 run 的类型化事实。
- **活动行一律单个 `-ing` 动词。** `thinking` / `concluding` / `executing {name}` / `reading` / `planning` / …
- **所有错误共用一条通往 stderr 的路：`Result` 走回同一个渲染件。** 形状是 `error: 一句话`；空行只为同一条流上已经打出的字段（摘要后面），stderr 上单独出现时不加空行。
- **「指着的东西不在」归退出码 2，不归 1。** 1 的含义是「reviewbot 自己出了事」；把用户敲错的路径混进去，CI 会把自己的笔误读成崩了。
- **`--help` / `--version` 不是失败，是输出。** 走 stdout、退出 0。

## CLI

- **命令顺序按生命周期：`config` → `review` → `run`。** 先配置，再评审，再管 run。
- **每个子命令与每个参数都有帮助文案，缺短说明或该有的长说明就失败。** 新命令不写说明落不了地。四条值得长说：评审目标可以是什么、清理是唯一会删东西的命令、`config check` 全程本地不发请求、`config info` 印的是库存不是某次调用。
- **看工具印契约，不印「注册了没有」。** 「未注册」是某一次调用的事实。顶层 catalog 删掉之后，同一信息进 `config info`：文本只留名字、用途、轮次，完整契约在 JSON。
- **`config init` 写示例配置，已有文件不覆盖。** 真正空白过不了校验；覆盖是不可逆的。模板随二进制走（`src/config/example.toml`），不是 `examples/` 旁路文档。`[[tool]]` 全部注释：列在文件里就是启用，init 不该假定本机有检查器。
- **`config check` 是结论，`config info` 是目录。** 两套视觉语言；check 不复用 info 的记录块。catalog 四条顶层命令不留：同一信息进 `config info`。
- **`run remove` 成功不打字；`run prune` 成功一句个数。** 要看留下哪些用 `run list`。
- **`run list` 的 STAGES 只报最远那个。** 阶段有固定顺序；JSON 仍是列表。
- **`run trace` 看某一个 run 的对话，不另起顶层命令。** 一次 run 多份 trace；run 级过程在 `log`。id 由路径（加分片）哈希，与 `run_id` 同形；列出按落盘时间。
- **只收 unified diff，不收 patch 系列。** 评的是净变更；还原补丁系列必须写盘。没有 `--diff`：猜错必然当场炸。
- **`--worktree` 只能当场给，不自动探测，不写进配置。** 猜错会静默读到另一个仓库；HEAD 必须等于 `head_sha`。
- **HTTP 客户端一律带 User-Agent。** 这是传输层的事；403 的响应体必须进错误消息，不能把「令牌权限不足」当成 403 的唯一解释。浏览器 URL 只解析、HTTP 打 `base_url`。

## 安全（写入与读取）

- **工作树只读：接口没有写方法。** `--worktree` / `--output-dir` / `--runs-dir` 可以指进工作树（GitLab CI artifacts 只收项目目录内路径），但这两个目录自动进 `deny_paths`，防止把自己刚写出的报告读回去。
- **子进程那一半必须说实话。** reviewbot 保证自己不写，拦不住 `cppcheck` 往盘上写，除非容器只读挂载。写成「硬保证 + 依赖部署」。
- **changeset 里的文件不享有豁免。** 被 `deny_paths` 命中的路径即便出现在 diff 里也不读全文。可读范围的边界是仓库不是 changeset。
- **压制型注入承认拿不下。** 空列表是合法输出，跟「确实没问题」区分不开；双模型比对翻一倍的钱只换来弱信号。

## 编码与测试

- **编码管代码长什么样，测试管行为落在哪一档；两条 rule，有 `.rs` 才加载。** 不靠「去设计里找」。
- **独立实体必须实例化；禁止产品路径 `unwrap` / `expect`。** 测试夹具的 `unwrap` 留下。不另起 `Run` / `orchestrator`。
- **源码注释用英文。** `docs/` 与 `.cursor/rules/` 本身是中文文档；测试字符串里的 CJK 是被测输入，不改。
- **测试只在最低够用的那一档测。** 不要测判不了的、合法空输出、退出码不含业务结论。
- **示例配置必须能通过校验。** 没有默认值可以替它兜底，而那份文件是唯一会被人抄走的文档。
- **探二进制一律带 `--config` 与 `--runs-dir` 指向临时目录。** 不碰 `~/.reviewbot`，也不删仓库以外的任何东西。
- **这个仓库一处 `#[allow]` 都没有。** 错误体积用装箱解决。
- **不再写对话记录。** 取舍进本文；现行设计仍以 `design.md` 为准。`docs/conversations/` 只作历史原文，不再追加。
- **`prototype.md` 是原型实现计划，不是现行路线图。** M1–M8 已经做出当前这棵树；未做的缺口和下一步在 README，不在这份计划上续写里程碑。文件名跟标题对齐，避免看起来还是一份待执行的 implementation plan。
